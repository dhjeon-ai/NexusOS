# ProjectOS Task Lifecycle

## Purpose

Use task pages only when work is large enough to benefit from continuity.

## Create a task page when

- the work touches three or more files
- a new module or service is introduced
- a contract or behavior changes
- the work may span multiple sessions
- a handoff may be needed later

## Keep inside the task page

- goal
- scope
- touched components
- acceptance criteria
- current status

## Do not use task pages for

- tiny one-file edits
- trivial text fixes
- temporary exploration with no contract impact

## Close-out rules

- update affected component pages
- update architecture pages if a cross-cutting rule changed
- archive the task page when complete
- keep current-session notes in the root status file, not in the task archive
